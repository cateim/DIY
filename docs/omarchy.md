# 🐧 Omarchy no Alienware (personalizações e reinstalação)

Tudo o que foi mudado de propósito no Omarchy 4 do notebook Alienware 17 R3 (hostname `alienware`) desde a instalação em 31/10/2026, com os arquivos e os scripts para devolver cada mudança numa reinstalação do zero. O repositório é público: dados pessoais (domínio, e-mail, nomes dos servidores, endereço `.onion`) viram placeholders `<<NOME>>` e segredos nunca entram. Os valores reais ficam num `private.env` fora do git, com cópia no Bitwarden.

**Pré-requisito:** Omarchy 4 instalado ([omarchy.org](https://omarchy.org/)). Para o Docker deste notebook no Portainer central, veja [`portainer-agent.md`](./portainer-agent.md).

Os arquivos e os scripts estão em [`assets/omarchy/`](../assets/omarchy/).

> ℹ️ Este guia é também o inventário. Mudou ou removeu alguma personalização no notebook? O DIY é atualizado na mesma sessão, pelo roteiro da [Parte 6](#parte-6-mantendo-o-diy-em-dia).

## Parte 2: Reinstalação do zero

1. **Omarchy 4** pela ISO. Sistema com LUKS no Samsung e `/home` no Crucial (LUKS2 + btrfs, destravado por keyfile em `/etc/cryptsetup-keys.d/`). Os scripts de disco da migração ainda não estão no DIY (veja [Notas Importantes](#notas-importantes)).
2. **DIY numa pasta temporária**, porque o `~/Drive` só volta depois do drive-sync (Parte 5):

   ```bash
   git clone https://github.com/cateim/DIY.git /tmp/DIY && cd /tmp/DIY
   ```

3. **Pacotes** (uns 20 minutos):

   ```bash
   omarchy pkg add $(grep -vE '^\s*(#|$)' assets/omarchy/packages.txt | cut -d' ' -f1)
   omarchy pkg aur add $(grep -vE '^\s*(#|$)' assets/omarchy/packages-aur.txt | cut -d' ' -f1)
   flatpak install -y flathub $(grep -vE '^\s*(#|$)' assets/omarchy/flatpak.txt | cut -d' ' -f1)
   omarchy pkg drop ghostty ghostty-shell-integration ghostty-terminfo
   ```

   Tailscale e Voxtype têm passo próprio na [Parte 5](#parte-5-passos-manuais).

4. **private.env**: copie a nota "DIY Omarchy private.env" do Bitwarden para `~/.config/diy-omarchy/private.env` e rode `chmod 600` nele.
5. **Arquivos** (uns 2 minutos):

   ```bash
   assets/omarchy/install.sh --system --dry-run   # confira a lista
   assets/omarchy/install.sh --system
   ```

6. **Recarregar** com os comandos que o `install.sh` imprime no fim: `hyprctl reload`, `omarchy restart shell`, as units do usuário, `udevadm` e `limine-mkinitcpio`.
7. **Arranjo das telas** (o `monitors-arranjo.tsv` não vem do DIY, veja `monitors-arranjo.lua` na Parte 3.1): com as telas conectadas e o shell já reiniciado, grave o arranjo atual uma vez. Responde `ok`; com o arquivo já existente responde `recusado: existe` e não muda nada. Sem esse passo o arquivo nasce no primeiro Manter do painel (`SUPER + ALT + P`).

   ```bash
   OMARCHY_SHELL_IPC_TIMEOUT=15s omarchy-shell shell call cateim.arranjo-telas semear ""
   ```

8. **Passos manuais** da [Parte 5](#parte-5-passos-manuais).

## Parte 3: Inventário dos arquivos

### 3.1 Hyprland (`~/.config/hypr/`)

| Arquivo                | O que muda                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| :--------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bindings.lua`         | `SUPER + E` abre o Nautilus. `SUPER + SHIFT + E` e `SUPER + SHIFT + C` abrem Gmail e Google Agenda no lugar do HEY. `SUPER + H` abre o histórico da área de transferência. `SUPER + SHIFT + S` tira print de uma região (era o Google Maps). `CTRL + SHIFT + F12` troca o monitor do VNC. `SUPER + CTRL + ↑/↓` move a janela para o monitor de cima ou de baixo. `SUPER + SHIFT + J` iguala as janelas do workspace (veja `igualar-janelas.lua`). `ALT + TAB` abre o switcher com miniaturas (submap `cateim-switcher`), menos no Windows VM, onde o Alt+Tab vai para o Windows. Desde a migração do Omarchy 4.5, `SUPER + CTRL + X` e `F9` (segurando) ligam o ditado do voxtype; a 4.5 também liga `ALT + ESPAÇO` e o Alt direito, que no `us intl` e no `br` é AltGr e não dispara o atalho. `SUPER + ALT + P` abre o painel de arranjo das telas (plugin `cateim.arranjo-telas`, como o Win + P do Windows).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `igualar-janelas.lua`  | Módulo do `SUPER + SHIFT + J`: no layout tiling (dwindle), deixa as colunas com a mesma largura e as linhas com a mesma altura. O dwindle não tem comando para isso, e 3 janelas lado a lado ficam em 50/25/25. O Hyprland não mostra a árvore do dwindle, então o módulo descobre o pai de cada janela mexendo no `splitratio` (só vale para o pai da janela com foco) e acerta cada divisão pelo número de colunas ou linhas de cada lado. Tudo roda numa chamada Lua só, sem quadro intermediário; o foco, o cursor e a ordem do Alt+Tab entre as janelas voltam como estavam. Limite: uma divisão com grupos de janelas dos dois lados não tem janela filha direta e fica como está, com notificação. Em workspace scrolling ou com tela cheia, só avisa.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `hyprland.lua`         | O Bitwarden (app e janela da extensão no Chrome) volta a aparecer em captura de tela, para aprovar login pelo VNC e pelo SelfDesk. Efeito colateral: aparece também em compartilhamento de tela e gravação. Logo depois do `require("hypr.monitors")`, um `pcall` chama o `monitors-arranjo.lua`: um erro dele não impede o resto da config (atalhos inclusive).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `input.lua`            | Teclado `us` (intl) e `br`; rolagem natural só no touchpad.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `monitors-arranjo.lua` | Carregador do arranjo das telas (plugin `cateim.arranjo-telas`, Parte 3.2). A cada carga do Hyprland, lê o `~/.config/hypr/monitors-arranjo.tsv` que o painel grava no Manter e mescla posição, modo e orientação das telas externas nas regras que já existem no `monitors.lua`. Só mescla: tela sem regra própria não recebe nada, a escala continua sendo a da regra e o notebook (`eDP-1`) nunca é alvo. O arquivo é só dado (nada dele vira código) e vale tudo ou nada: uma linha inválida invalida o arquivo, e aí valem só as regras do `monitors.lua`. O `monitors-arranjo.tsv` fica fora do espelho por privacidade, porque guarda a descrição e o serial de toda tela já conectada, inclusive de clientes; numa máquina nova ele se refaz pelo painel (o primeiro Manter) ou pelo `semear` (Parte 2, passo 7).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `monitors.lua`         | Tela do notebook 2560x1440@120, escala 1,25, na origem (`0x0`), e o LG UltraWide 2560x1080@75 em cima, centralizado (`-256x-1080`). A tela portátil (RTK FHD, 1920x1080@60) na porta Thunderbolt/USB-C fica à direita do notebook, encostada e centralizada na altura (`2048x36`); sem regra, o `auto` a punha à direita do LG, em `2304x0`, com um vão de 256 px que o mouse não atravessava. O LG e a portátil têm duas regras iguais cada, pela descrição e pela porta (`HDMI-A-4` e `DP-1`): desde o Omarchy 4.5 o painel Display religa a tela pelo nome e mantém modo e posição da regra com esse nome; só com a regra pela descrição o LG voltava à direita, a 60 Hz. `omarchy_gdk_scale` e `omarchy_monitor_scale` são do controle de escala do Omarchy e só valem para o `GDK_SCALE` e para tela sem regra própria; ficam em 1, porque desde a 4.5 o `GDK_SCALE` segue a menor escala arredondada (com 2, os apps GTK do XWayland abriam com o dobro do tamanho). O notebook fica em `0x0` por causa do SelfDesk (RustDesk): o `xdg-desktop-portal-hyprland` informa toda tela compartilhada em `(0,0)`, e com o notebook em outra posição o mouse remoto caía no LG. Numa sessão do SelfDesk o LG e a portátil (toda tela além do notebook) ficam desligados (veja `selfdesk-tela-unica` na Parte 3.6). Desde 20/11/2026 as regras por tela são âncoras e plano B: posição, modo e orientação das telas externas vêm do arranjo (`monitors-arranjo.lua`), mesclados nessas regras, e as daqui valem sozinhas quando o arranjo falta ou é inválido. Uma porta nova só vira posicionável no painel depois de o Omarchy gravar a regra dela (os botões de escala do painel Display fazem isso). |

Os motores do REA que não vêm do pacman (Kuna, Wakaru e o JAR do JADX, em `~/.local/share/rea`, e o Unblob acima), as ferramentas de engenharia reversa avulsas de 20/11/2026 (Frida e `ilspycmd` acima, Cutter, Binary Ninja Free e IDA Free), o `msr-tools` e o UEFITool de 22/11/2026 (análise do firmware e do Boot Guard) e as variáveis `REA_*` do registro estão na [Parte 6 do guia do REA](./rea.md#parte-6-motores-opcionais-instalar-quando-a-tarefa-pedir).

O ESP-IDF 5.5.5 do Jade fica em `~/esp`, com um venv próprio, e não está no DIY.

O Rust vem do pacote `rustup` da lista, com os toolchains em `~/.rustup`. Não rode o `omarchy install dev-env rust` (no menu, Install > Development > Rust): ele baixa o instalador oficial, que põe um segundo `rustup` em `~/.cargo/bin`, na frente do pacman, e acrescenta o `~/.cargo/env` no `.bashrc` depois do `ble-attach`, no `.profile` e no `.bash_profile`. Se rodar por engano, apague o `~/.cargo` e o `~/.profile` que ele criou e tire a linha dos outros dois. O `omarchy remove dev-env rust` não serve, porque roda o `rustup self uninstall`, que apaga também o `~/.rustup` do rustup do pacman.

**LSPs dos plugins do Claude Code**: os 10 plugins LSP ligados (C/C++, C#, Go, Java, Lua, PHP, Python, Ruby, Rust e TypeScript) acham o servidor pelo PATH. Os pacotes estão na seção própria da `packages.txt` e da `packages-aur.txt`; o `clangd` vem do `clang` do Omarchy, o `gopls` da seção de desenvolvimento e o `rust-analyzer` do `rustup component add` acima. O `dotnet-sdk` sem versão vai na lista do pacman de propósito, para entrar antes do `csharp-ls` do AUR: sozinho, o `csharp-ls` puxaria o `dotnet-sdk-10.0`, que conflita com o `dotnet-runtime` do Omarchy (usado pelo Pinta). Os dois ajustes de arquivo estão na [Parte 3.9](#39-lsps-dos-plugins-do-claude-code). Testados em 07/11/2026 abrindo um arquivo com erro em cada linguagem: os 10 devolveram o diagnóstico (o `ruby-lsp` pelo modelo pull, `textDocument/diagnostic`). O `csharp-ls` e o `rust-analyzer` só sobem em pasta com projeto (`.csproj` ou `.sln`, `Cargo.toml`).

**Claude Desktop**: o `claude-desktop` vem do repositório do Omarchy, que reempacota o beta oficial do Claude para Linux, e está na seção de desenvolvimento da `packages.txt`. Fora da reinstalação, o caminho é o menu (Install > AI > Claude Desktop) ou o `omarchy-install-ai-claude`. Não tem atualizador próprio: atualiza com o `omarchy update`. O estado do app (`~/.config/Claude`, com a sessão logada) fica fora do espelho; o `omarchy-remove-ai-claude` apaga ele e o `~/.cache/Claude`, sem tocar no `~/.claude` do Claude Code CLI. Instalado em 07/11/2026 (versão 4.23118.0).

**Apps próprios**, empacotados a partir do repositório local (não estão em repositório nenhum, então ficam fora das listas): o DriveSync (`~/Drive/GitHub/drive-sync`, repositório `CaTeIM/drive-sync`; chamado SyncWatch até 11/11/2026 e drivesync até 14/11/2026, e o repositório se chamou `drivesync` até 20/11/2026; o AUR já tem um `drivesync` de outro projeto), uma janela com o estado do drive-sync, as rodadas recentes do log com o que mudou em cada lado e as cópias `.conflictN` do `~/Drive`, mais o widget `drive-sync` da barra, que vem no pacote: nuvem com check, com setas (esmaecida) durante a rodada ou com alerta quando há problema, e um painel com a última sincronização, a última rodada, a próxima, desde quando está falhando e o erro do log, com botões e teclas para sincronizar agora (S, também o clique direito), pausar uma hora ou retomar (P), abrir a janela (W, focando a que já estiver aberta) e abrir o `~/Drive` (O, também o clique do meio); `?` lista as teclas. Janela e widget mostram o mesmo estado, o do `drive-sync status --json`. Desde 10/11/2026 o DriveSync também roda o drive-sync (veja `drive-sync` na 3.6): na janela, S sincroniza, P pausa (uma hora, até as 8:00 ou até retomar) e U retoma. Instala com `~/Drive/GitHub/drive-sync/bin/install` (compila, roda o `makepkg -fsi` e pede o sudo) e aparece no lançador (`SUPER + SPACE`). O pacote não escreve na home, então, numa reinstalação, o widget só carrega depois de abrir o DriveSync uma vez: é ele que cria o link `~/.config/omarchy/plugins/drive-sync`, que fica fora do espelho, enquanto o `shell.json` do espelho já traz o widget na barra. Para remover: `sudo pacman -R drive-sync`.

## Parte 5: Passos manuais

Tudo o que não é arquivo do espelho, na ordem em que faz sentido numa reinstalação.

1. **Tailscale**: `omarchy install service tailscale`, login, depois `sudo tailscale set --hostname=alienware`. No painel do Tailscale, desligue a expiração da chave deste nó.
2. **Drive**: pela primeira configuração do próprio DriveSync. O repositório dele mora no `~/Drive`, que ainda não voltou, então clone numa pasta temporária, como o DIY. O build só tem o client OAuth do DriveSync com o `src/oauthclient.local.h`, que fica fora do git: crie a partir do `oauthclient.local.h.example` antes de instalar, com o ID e o secret do client que estão no Bitwarden.

   ```bash
   git clone https://github.com/CaTeIM/drive-sync.git /tmp/drive-sync && cd /tmp/drive-sync
   cp src/oauthclient.local.h.example src/oauthclient.local.h   # preencha com o client do DriveSync (Bitwarden)
   bin/install
   ```

   Confira que o `~/.config/drive-sync/machine.json` voltou com o `install.sh` da Parte 2 (ele segura a configuração sem o `/home` do Crucial). Depois abra o DriveSync, aperte `T`, entre com o Google no navegador, escolha a pasta `~/Drive`, no passo dos filtros importe o `/tmp/DIY/assets/omarchy/drive-sync-filters.txt` e confirme o dry run do conserto. Ele cria a conta `account1` e liga o `drive-sync@account1.timer` (veja `drive-sync` na 3.6). O `rclone.conf` tem o token do Google e nunca entra no DIY. O `drive-sync.sh` e o `drive-sync-aviso` de [`scripts/`](../assets/omarchy/scripts/) são o jeito antigo (remoto `gdrive` e assunção com `T`), guardados só como referência.
3. **Cloudflare Tunnel**: grave o token do túnel em `/etc/cloudflared/token` (root, modo 600) e rode `sudo systemctl enable --now cloudflared`. No Cloudflare One, o hostname `remote.<<DOMAIN>>` aponta para `tcp://localhost:5900`, atrás do Cloudflare Access.
4. **wayvnc**: gere a chave RSA dos clientes nativos e ligue o serviço:

   ```bash
   ssh-keygen -m pem -f ~/.config/wayvnc/rsa_key.pem -t rsa -N ""
   systemctl --user enable --now wayvnc.service vnc-sessao.service
   ```

5. **SelfDesk** (o RustDesk da Self-Labs, já apontado para o servidor próprio): `sudo pacman -U https://github.com/self-labs/selfdesk/releases/latest/download/selfdesk-x86_64.pkg.tar.zst` (o pacote liga o `SelfDesk.service` sozinho e conflita com o `rustdesk`), depois `systemctl --user enable --now selfdesk-tela-unica.service`. Ele não vem de repositório: versão nova é o mesmo `pacman -U`. Para manter o ID de uma instalação anterior, copie o `/root/.config/rustdesk/RustDesk.toml` para `/root/.config/selfdesk/SelfDesk.toml` com o serviço parado (o mesmo vale para os `RustDesk*` do `~/.config/rustdesk`, menos o `RustDesk2.toml`), como fez a migração de 20/11/2026 (veja o [`rustdesk-server.md`](./rustdesk-server.md)).
6. **NAS** (CIFS em `/mnt/nas/midia`): crie o arquivo de credenciais (root, modo 600) e a linha do `/etc/fstab`:

   ```
   //<NAS>/midia /mnt/nas/midia cifs credentials=<arquivo>,uid=1000,gid=1000,file_mode=0664,dir_mode=0775,iocharset=utf8,vers=3.1.1,_netdev,nofail,x-systemd.automount 0 0
   ```

7. **Desbloqueio do LUKS por SSH no boot** (só pelo cabo): preencha `BOOT_*` e `UNLOCK_ROOT_KEYS` no `private.env` e rode [`assets/omarchy/scripts/ssh-no-boot.sh`](../assets/omarchy/scripts/ssh-no-boot.sh). Ele tira um snapshot antes, instala os hooks, gera o initramfs e confere tudo. Se acusar falha, não reinicie.
8. **Portainer Agent**: `sudo systemctl enable docker.service` primeiro. O Omarchy liga só o `docker.socket`, e sem isso o Docker e o agent só sobem no primeiro uso do Docker, não no boot. Depois siga o [`portainer-agent.md`](./portainer-agent.md).
9. **Voxtype**: aceite o convite "Install Dictation with Voxtype" do Omarchy.
10. **Luz do G903** (perfil gravado na memória do mouse):

    ```bash
    omarchy pkg add libratbag && sudo systemctl start ratbagd
    ratbagctl list                     # nome do mouse, ex.: warbling-mara
    ratbagctl <mouse> profile 0 led 0 set mode cycle duration 8000 brightness 255
    ratbagctl <mouse> profile 0 led 1 set mode cycle duration 8000 brightness 255
    omarchy pkg drop piper libratbag
    ```

11. **Apps**: os PWAs do Chrome voltam pelo sync da conta Google; o SideSwap é um AppImage baixado em `~/Applications/SideSwap.AppImage`.
12. **Agente SSH** (a senha de uma chave é pedida uma vez por login, não a cada `ssh`): ligue o agente do pacote `openssh` e ponha o bloco abaixo no fim do `~/.ssh/config`. O `IdentityAgent` faz o agente valer também para quem não herdou o `SSH_AUTH_SOCK`, como o Antigravity e o Claude Code. O `~/.ssh/config` fica fora do espelho, porque lista os servidores dos clientes.

    ```bash
    systemctl --user enable --now ssh-agent.socket
    ```

    ```text
    Host *
        AddKeysToAgent yes
        IdentityAgent ${XDG_RUNTIME_DIR}/ssh-agent.socket
    ```

    O primeiro `ssh` depois do login pede a senha e deixa a chave no agente até reiniciar ou sair da sessão. Para ver o que está carregado: `SSH_AUTH_SOCK=$XDG_RUNTIME_DIR/ssh-agent.socket ssh-add -l`.

13. **Ícones das pastas** (depois do `~/Drive`, passo 2): a cópia de `~/.local/share/icons/pastas/` fica no Google Drive, em `~/Drive/Omarchy/icones-pastas/`, e volta junto com o `~/Drive`. Copie de volta e rode:

    ```bash
    mkdir -p ~/.local/share/icons/pastas
    cp -a ~/Drive/Omarchy/icones-pastas/. ~/.local/share/icons/pastas/
    icones-pastas && nautilus -q
    ```

    A pasta dos ícones não está no DIY porque tem logos e nomes de projetos de cliente, e por isso a cópia fica no Drive, que é privado. Ícone novo ou trocado vai para as duas pastas. O metadata do gvfs (`~/.local/share/gvfs-metadata/`) também fica de fora: é binário e guarda o estado de todos os arquivos, não só o dos ícones.

14. **OCI CLI** (depois do `uv tool install` da Parte 4): gere a chave da API no próprio notebook:

    ```bash
    ( umask 077; mkdir -p ~/.oci
      openssl genrsa -out ~/.oci/oci_api_key.pem 2048
      openssl rsa -pubout -in ~/.oci/oci_api_key.pem -out ~/.oci/oci_api_key_public.pem
      echo OCI_API_KEY >> ~/.oci/oci_api_key.pem )   # rótulo que o CLI pede; sem ele, avisa a cada comando
    wl-copy < ~/.oci/oci_api_key_public.pem
    ```

    No console do OCI, no usuário que o CLI vai usar: **API keys** → **Add API key** → **Paste a public key**, cole e adicione. Grave em `~/.oci/config` o trecho que o console mostra (**Configuration file preview**), com `key_file=~/.oci/oci_api_key.pem`, rode `chmod 600 ~/.oci/config` e teste com `oci iam region-subscription list`. Prefira um usuário com o mínimo de permissão que o uso pede. O `~/.oci` nunca entra no DIY: a chave privada dá acesso à conta.

## Parte 6: Mantendo o DIY em dia

Vale para toda personalização nova, mudada ou removida no notebook, na mesma sessão:

1. Mude o arquivo real no sistema, nunca o espelho.
2. Arquivo novo: uma linha no `files.txt`. Removeu: tire a linha.
3. Rode `assets/omarchy/export.sh`. Se ele acusar segredo, ponha o valor no `private.env` (e o nome em `PLACEHOLDER_KEYS` do `export.sh`, se for chave nova).
   Arquivo dentro de pasta só do root (como o `/etc/polkit-1/rules.d/`) o usuário nem enxerga: o `export.sh` confere com `sudo test -f` e copia com `sudo cat`, então pede a senha no terminal; rode-o num terminal, não por um agente sem `sudo`. O espelho continua sendo do usuário.
4. Atualize a tabela certa deste guia (Parte 3, 4 ou 5) e o `[Unreleased]` do [`CHANGELOG.md`](../CHANGELOG.md).
   Se a personalização copia algo do Omarchy ou depende de um comportamento dele, ponha uma linha no `~/.config/vigia-omarchy/vigiados.conf` e rode `vigia-omarchy` uma vez.
5. Valor novo no `private.env`: atualize a nota do Bitwarden.
6. Commit com escopo `omarchy`, por exemplo `docs(omarchy): add the window switcher plugin`.

Filtro do drive-sync mudado no DriveSync: copie o `~/.config/drive-sync/filters.txt` para o `assets/omarchy/drive-sync-filters.txt`, byte a byte (`cp`). Do `~/.config/drive-sync/` só o `machine.json` entra no `files.txt`; a config e os filtros ficam de fora de propósito (veja a Parte 3.6).

## Notas Importantes

- O repositório é público. Senha, token, chave e o `.onion` ficam só no `private.env`, com cópia no Bitwarden; o `export.sh` se recusa a terminar se achar um deles no espelho, chave de API (`sk-ant-`, `*API_KEY=` com valor) incluída. Uma chave que o shell usa mora num arquivo próprio fora do `files.txt`, nunca no `~/.bashrc`.
- Os scripts de disco da migração (formatação do Crucial, cópia do NAS) estão em `~/Documents/Migracao-Omarchy`, ainda fora do DIY: formatam disco e precisam de revisão antes de virar guia.
- Estado de app (perfis do navegador, Antigravity, Bitwarden, Telegram) não entra no espelho: volta pelo login ou pelo sync de cada app.
- Não mude o arranjo das telas (`SUPER + ALT + P`) com uma sessão do SelfDesk aberta: o servidor guarda o arranjo do início da sessão e converte cada posição do mouse dele para o arranjo atual (comentário do `selfdesk-tela-unica`), e o mouse remoto se desalinha. O painel não detecta a sessão; mude antes de conectar ou depois de desconectar.
- O `~/.claude` (Claude Code) fica fora deste guia por decisão, menos os agentes de `~/.claude/agents/` ([Parte 3.10](#310-agentes-do-claude-code-claudeagents)): o resto tem conteúdo pessoal e outro ciclo de vida.
